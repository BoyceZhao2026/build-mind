## 1. 分析范围与结论摘要

分析对象：

- 论文：[MultiMath: Bridging Visual and Mathematical Reasoning for Large Language Models](https://arxiv.org/abs/2409.00147)
- 数据集：[pengshuai-rin/multimath-300k](https://huggingface.co/datasets/pengshuai-rin/multimath-300k)
- 代码仓库：[pengshuai-rin/MultiMath](https://github.com/pengshuai-rin/MultiMath)
- 本地数据：项目根目录下的 `data/data.json`、`data/images.zip`、`data/caption/` 和 `data/solution/`

本次分析日期为 2026-08-17。本地 Hugging Face 数据对应提交 `e777c2c1a205717dce6e8f0747fb4a40184fea3f`。分析包含论文、作者仓库、完整本地 JSON、图片压缩包目录和若干数据样本；没有训练 MultiMath-7B，也没有重新执行论文中的完整基准测试。

核心结论：

1. MultiMath-300K 是一个面向**多模态数学模型训练**的数据集，不是教学对话数据集，也不是可以直接驱动语音老师的课程脚本。
2. 它的主要价值在于把同一道 K12 数学题组织成“题干 + 单张图片 + 中英文图片描述 + 中英文逐步解法”，同时支持视觉语言对齐和完整解题训练。
3. 当前发布物中有 41,119 条六年级记录，占根数据的 13.77%，远多于 CMMaTH 等公开中文多模态基准中的六年级样本，对当前项目有较高的题目候选池价值。
4. 六年级数据覆盖组合图形面积、整数小数应用题、百分数、行程、统计图、圆柱体积等内容；但它的知识点体系与我们定义的和差、倍数、分数、百分数、行程、工程、年龄七类应用题并不直接对应，需要重新映射。
5. 数据中的 caption 和 solution 主要由 GPT-4o/GPT-4 自动生成并经过答案一致性筛选。它们应视为“待验证的弱标注”，不能直接视为视觉事实或教学金标准。
6. 本地抽查已经发现图片描述错误：一张价格图中间物品清楚写着“牙膏”，自动 caption 却描述为“香皂”。这说明即使最终解答正确，视觉描述也可能发生对象绑定错误。
7. 论文报告的 298,670 题与当前根 `data.json` 的 298,677 条相差 7 条；四类聊天文件与根文件之间也存在缺失和口径差异。接入时不能假设所有文件是一一对应的。
8. 根数据中的 298,677 个图片引用均能在 `images.zip` 中找到，ID 和图片引用均无重复，这是发布物较好的方面；但压缩包还包含 54,399 张未被根数据引用的图片，不应无差别导入。
9. 论文中的 MultiMath-7B 在 2024 年对 MathVista、MathVerse 和部分文本数学任务表现较强，但“开源 SOTA”是当时结论，不能作为 2026 年模型选型依据。
10. 对 `voice-tutoring` 最合理的用法是：把六年级子集作为**候选题库和弱标注来源**，经过图片核对、数学验证、题型重标、教学结构转换和人工审核后，建设我们自己的 silver/gold 数据。
11. 不建议把原始完整解法直接放入实时教学上下文，也不建议把它们直接用作答案防泄露、学生步骤判断或教学策略训练数据。
12. 数据集的商业使用边界不够清晰。代码仓库是 Apache-2.0，但论文只明确说明题库获得了“研究用途”许可，Hugging Face 数据仓库没有单独的数据许可证文件；正式商用前需要取得书面确认。

## 2. 论文试图解决什么问题

论文关注的是数学大模型与通用多模态模型之间的能力断层：

- 数学专用 LLM 擅长文本数学推理，但不能读取几何图、统计图、函数图等视觉信息；
- 通用多模态模型能看图，但数学推理能力通常弱于数学专用模型；
- 当时已有的数学多模态工作多集中于几何题，或在多模态微调后显著损伤文本数学能力。

作者提出两项核心产物：

1. **MultiMath-300K**：包含图像描述和逐步解法的中英双语 K12 多模态数学数据集；
2. **MultiMath-7B**：以 DeepSeekMath-RL-7B 为语言基础、使用 LLaVA 式视觉架构和四阶段训练流程构建的多模态数学模型。

论文的关键设计思想不是“让通用视觉模型多学一点数学”，而是：

```text
先从已经具备数学推理能力的语言模型出发
→ 添加视觉编码和模态适配
→ 学会描述数学图片
→ 学会视觉问答
→ 学会基于图片执行逐步数学推理
→ 用步骤级奖励进一步纠错
```

这个方向对当前项目的启发是：视觉理解和数学推理不能只靠一次端到端提示词完成。即使最终使用强闭源模型，工程上仍应区分题图事实、题目结构、数学解法和教学策略。

## 3. MultiMath-300K 是什么

### 3.1 论文给出的数据定位

论文将 MultiMath-300K 描述为：

- 多模态：每题恰好有一张图片；
- 多语言：题干、caption 和 solution 均提供中文与英文；
- 多年级：覆盖小学一年级到高中三年级；
- 多步骤：解答以分步推理形式呈现，最终答案使用 `\boxed{}`；
- 多任务：同时提供视觉语言对齐数据和数学指令数据；
- 多领域：涵盖算术、代数、数学概念、平面几何、立体几何、函数和算法等。

论文统计为：

| 数据拆分 | 论文题数 |
| --- | ---: |
| 训练集 | 290,227 |
| 验证集 | 8,443 |
| 合计 | 298,670 |

这里的“300K”是近似名称，不是精确等于 300,000。

### 3.2 它与评测基准的区别

MultiMath-300K 首先是**训练数据**。它与 MathVista、MathVerse 这类测试基准不同：

| 维度 | MultiMath-300K | MathVista / MathVerse |
| --- | --- | --- |
| 主要用途 | 模型对齐和指令训练 | 模型评测 |
| 是否提供完整解法 | 是 | 视基准而定，通常以答案评测为主 |
| 是否提供图片描述 | 是 | 部分提供或可另行生成 |
| 是否适合报告独立泛化能力 | 不适合直接自测 | 更适合 |
| 是否可直接成为教学脚本 | 否 | 否 |

如果模型使用 MultiMath-300K 训练，就不能再从同一数据集中随机抽题并把结果称为独立能力评测。需要按来源、模板、图片和语义相似度去重后另建测试集。

## 4. 数据集构建流程

论文描述的流程可以概括为：

```text
K12 教材、练习和考试题库
→ 完整性、单图、多模态和清晰度筛选
→ 约 39 万道原始题
→ GPT-4 翻译为中英双语
→ GPT-4o 生成中英文图片描述
→ MathPix 校正公式和文本类 OCR
→ GPT-4o 基于原解答生成逐步推理链
→ 与标准答案比对并修订
→ GPT-4 再次验证，只保留答案正确的记录
→ MultiMath-300K
```

### 4.1 原始题目筛选

作者要求原始题目满足：

- 题目、详细解答和标准答案完整；
- 每题恰好包含一张图片；
- 图片不能过小或过于模糊；
- 题目来自获得授权的 K12 题库；
- 过滤涉及学生隐私的内容；
- 使用 n-gram 与已有数学数据比较，过滤重复题。

论文附录进一步说明，题目来自学库宝题库，作者购买了题库使用权，并获得研究用途许可。

### 4.2 图片描述生成

图片描述由 GPT-4o-2024-05-13 生成。其用途有两个：

1. 训练视觉编码器与语言模型之间的对齐；
2. 把视觉信息转成文本，使文本模型也能尝试解答多模态问题。

MathPix 被用于核验和修正公式、文本类图片中的 OCR 结果。但这不等于所有几何关系、物体类别、位置关系和图表数值都经过人工核验。

### 4.3 逐步解法生成

逐步解法经过三轮自动流程：

1. GPT-4o 使用原始详细解答作为提示，生成格式化分步解法；
2. 把生成结果与标准答案比较，如不一致则要求 GPT-4o 修订；
3. 把生成答案和标准答案提交给 GPT-4 验证，只保留判定正确的数据。

这一流程主要增强了**最终答案一致性**，但不能保证每个中间步骤、每个视觉事实、每个教学解释都正确。自动验证模型与生成模型还可能共享相似的错误偏好。

### 5.2 根数据的实际统计

对本地 `data/data.json` 流式解析得到：

| 数据拆分 | 根数据实际条数 | 论文条数 | 差异 |
| --- | ---: | ---: | ---: |
| `train` | 290,233 | 290,227 | +6 |
| `val` | 8,444 | 8,443 | +1 |
| 合计 | 298,677 | 298,670 | +7 |

这 7 条额外记录恰好是 6 条训练记录和 1 条验证记录，并且缺少题干和解答。solution 聊天文件仍然保持论文口径的 290,227 条训练记录和 8,443 条验证记录。

### 5.3 各聊天文件的实际条数

| 文件类型 | 训练条数 | 验证条数 |
| --- | ---: | ---: |
| 中文 caption | 290,118 | 8,444 |
| 英文 caption | 290,118 | 8,444 |
| 中文 solution | 290,227 | 8,443 |
| 英文 solution | 290,227 | 8,443 |

这说明：

- 根数据、caption 数据和 solution 数据不能通过数组位置直接对齐；
- 应使用 `id` 做连接键；
- 不同任务文件覆盖的 ID 集合不完全相同；
- Hugging Face 页面显示的大约百万级“rows”包含同一道题的中英文和不同任务视图，不代表有百万道独立题目。

### 5.4 图片完整性

本地核对结果：

| 项目 | 数量 |
| --- | ---: |
| 根数据记录 | 298,677 |
| 唯一 ID | 298,677 |
| 唯一图片引用 | 298,677 |
| 压缩包内图片文件 | 353,076 |
| 根数据引用但压缩包缺失 | 0 |
| 压缩包存在但根数据未引用 | 54,399 |

优点是所有根数据图片引用都能解析，而且没有重复 ID 或重复图片引用。缺点是压缩包保留了大量未被根数据引用的图片，可能来自筛选前的数据或未发布记录。构建索引时只应提取根数据实际引用的文件。

## 6. 数据结构和不同数据视图

### 6.1 根数据结构

每条根记录有统一的 13 个字段：

```json
{
  "id": "题目唯一 ID",
  "split": "train | val",
  "type": "选择题 | 填空题 | 解答题 | ...",
  "grade_band": "elementary school | middle school | high school",
  "grade": 6,
  "exam_point": "知识点标签",
  "image": "图片文件名.png",
  "title_zh": "中文题干",
  "title_en": "英文题干",
  "caption_zh": "中文图片描述",
  "caption_en": "英文图片描述",
  "solution_zh": "中文逐步解法",
  "solution_en": "英文逐步解法"
}
```

这个结构适合做数据发现、筛选和教师备课候选，但缺少：

- 结构化标准答案字段；
- 数学对象、单位和数量关系；
- 可执行的解题步骤依赖图；
- 多条候选解法；
- 常见错误和诊断问题；
- 提示等级和答案防泄露边界；
- 学生回答或多轮教学对话；
- 图片元素坐标、OCR 框和几何关系真值；
- 难度和课程版本等稳定教学标签。

### 6.2 caption 对话结构

caption 文件使用 LLaVA 风格：

```json
{
  "id": "...",
  "image": "...png",
  "conversations": [
    {
      "from": "human",
      "value": "题干 + <image> + 详细描述图片的指令"
    },
    {
      "from": "gpt",
      "value": "图片的自然语言描述"
    }
  ]
}
```

需要注意，caption 的生成输入包含题干，不是完全独立的 image-only 标注。因此 caption 可能混入题干事实、解题目标或模型推断，不能直接作为“图片中实际可见内容”的金标准。

### 6.3 solution 对话结构

solution 文件同样采用两轮对话：

```json
{
  "id": "...",
  "image": "...png",
  "conversations": [
    {
      "from": "human",
      "value": "题干 + <image> + 分步解答和 boxed 最终答案要求"
    },
    {
      "from": "gpt",
      "value": "Step 1 ...\nStep 2 ...\nAnswer: \\boxed{...}"
    }
  ]
}
```

它训练的是“看完题后一次生成完整答案”，而我们的产品需要“听学生说一步，再选择一个最小教学动作”。两者的交互目标明显不同。

## 7. 六年级子集分析

### 7.1 年级总体分布

本地根数据的学段分布为：

| 学段 | 数量 | 占比 |
| --- | ---: | ---: |
| 小学 | 59,061 | 19.77% |
| 初中 | 189,711 | 63.52% |
| 高中 | 49,905 | 16.71% |

六年级有 41,119 条，占全量 13.77%，其中训练记录 39,919 条，验证记录 1,200 条。小学数据明显集中于六年级，不能把“小学 59K”理解为各年级均衡覆盖。

### 7.2 六年级题型

| 题型 | 数量 | 六年级占比 |
| --- | ---: | ---: |
| 解答题 | 22,289 | 54.21% |
| 填空题 | 13,434 | 32.67% |
| 选择类合计 | 3,703 | 9.01% |
| 计算题 | 511 | 1.24% |
| 判断题 | 418 | 1.02% |
| 综合题 | 399 | 0.97% |
| 其他少量题型 | 365 | 0.89% |

大量解答题有利于获取自然语言解题候选，但其中 38,688 条全量题目属于多问结构。多问题在语音辅导中需要拆成多个子目标，不能直接按一条 solution 作为单一教学状态。

| 知识点 | 数量 |

| 组合图形的计数 | 952 |
| 图文应用题 | 951 |
| 数与形结合的规律 | 913 |
| 圆柱的侧面积、表面积和体积 | 734 |
| 扇形统计图 | 654 |
| 长方形、正方形的面积 | 623 |
| 角的度量 | 604 |

| 三角形的周长和面积 | 425 |

这说明 MultiMath-300K 的六年级优势更偏向**带图的面积、立体几何、统计图、图文应用和基础数量计算**。它与当前应用题 MVP 有交集，但不是同一个任务分布。

### 7.4 与当前七类应用题的粗略对应

对 `exam_point` 做关键词匹配得到：

| 关键词 | 六年级匹配数 | 注意事项 |
| --- | ---: | --- |
| 分数 | 1,702 | 与“百分数”标签存在重叠，不能直接相加 |
| 百分数 | 1,360 | 包含计算、统计图和实际应用等多种任务 |
| 行程 | 717 | 以简单行程为主，适合进一步筛选 |
| 倍数 | 212 | 很多是因数、公倍数和整除特征，不是倍数关系应用题 |
| 工程 | 92 | 数据量有限但可作为候选池 |
| 年龄 | 33 | 很少，需要自建数据补足 |
| 和差 | 15 | 只是标签文本命中，许多和差题可能被归入其他应用题标签 |

以上数字是标签字符串匹配，不是语义分类结果。接入时必须用规则和模型重新判定题型，不能直接把 `exam_point` 当作我们的 `problem_type`。

## 8. MultiMath-7B 的模型与训练方法

### 8.1 模型结构

MultiMath-7B 基于 LLaVA 架构，包含：

| 模块 | 论文使用方案 | 作用 |
| --- | --- | --- |
| 视觉编码器 | CLIP ViT-L/14-336 | 把 336×336 图片编码为视觉特征 |
| 多模态适配器 | 两层 MLP | 把视觉特征投影到语言模型空间 |
| 语言模型 | DeepSeekMath-RL-7B | 提供文本数学推理能力 |

336×336 分辨率在 2024 年属于常见 LLaVA 配置，但对密集小字、复杂统计图、长题截图和精细几何标记仍然可能不足。

### 8.2 四阶段训练

| 阶段 | 训练数据 | 主要训练对象 | 目标 |
| --- | --- | --- | --- |
| 1. 视觉语言对齐 | LLaVA-Pretrain + MultiMath caption + Geo170K-align | 只训练适配器 | 让数学语言模型接收视觉特征 |
| 2. 视觉指令微调 | LLaVA-Instruction | 全部模块 | 获得通用视觉理解和问答能力 |
| 3. 数学指令微调 | MultiMath solution + Geo170K-qa + MathV360K | 全部模块 | 把逐步数学推理扩展到视觉题 |
| 4. 步骤监督强化学习 | MultiMath-val + GSM8K + MATH + CMATH | 策略/奖励模型 | 在步骤级别发现并纠正推理错误 |

强化学习阶段的大致过程是：模型先生成多步解答，GPT-4o 判断错误并定位首个错误步骤，从该步骤重写正确解答；正确与错误路径组成偏好数据，训练奖励模型后再通过 PPO 优化策略模型。

这个思路与我们的“定位学生第一个错误步骤”有概念相似性，但论文定位的是**模型自身解题轨迹纠错**，不是识别儿童口语、理解多种学生方法或选择教学话术。

## 9. 实验结果应当如何理解

### 9.1 多模态数学结果

论文在 MathVista 和 MathVerse 的 `testmini` 上报告：

| 模型 | MathVista | MathVerse |
| --- | ---: | ---: |
| Math-LLaVA-13B | 46.6 | 20.1 |
| LLaVA-NeXT-34B | 46.5 | 16.6 |
| MultiMath-7B | 50.0 | 26.9 |
| GPT-4V | 49.9 | 54.4 |

MultiMath-7B 在当时的开源模型中表现突出，尤其在 MathVista 的几何问题和数学应用题子集上较强。但 MathVerse 的 Vision Only 子集仍是弱项，说明模型可能更多利用题干和训练获得的数学模式，而不是稳定读取纯视觉结构。

### 9.2 文本数学结果

| 模型 | GSM8K | MATH | CMATH | Gaokao-MathCloze |
| --- | ---: | ---: | ---: | ---: |
| DeepSeekMath-7B | 88.2 | 51.7 | 88.8 | 20.3 |
| MultiMath-7B | 79.2 | 46.3 | 84.2 | 28.8 |

MultiMath-7B 并没有完全保持基础模型的文本数学能力：GSM8K、MATH 和 CMATH 都有所下降，但高考填空题上提升明显。论文将后者归因于 MultiMath-300K 中包含大量高考风格数据。

这提示我们，多模态或领域微调可能造成能力偏移。不能只看某个综合平均分；至少需要分别评测六年级应用题、图片读取、学生步骤理解、教学引导和答案防泄露。

### 9.3 消融实验的意义

论文报告：

- 在相同文本化视觉输入下，MultiMath-7B 比未做多模态训练的 DeepSeekMath-RL-7B 高 9.1 分；
- 再加入真实图片输入，准确率提高 4.3 分；
- Stage 3 加入 MultiMath-300K 后，多项视觉和文本数学指标提升；
- 强化学习改善了 GSM8K、MATH、CMATH 和 MathVista，但降低了 MathVerse 和 Gaokao-MathCloze。

这些结果支持“数据分布和训练阶段会显著塑造能力”，也显示强化学习并不天然提升所有领域，域外退化必须通过独立回归集监控。

### 9.4 不能过度解读的地方

- 论文是 2024-08-30 提交的 arXiv v1，页面没有显示正式同行评审发表信息；
- “SOTA”仅针对论文当时纳入的开源模型，不能用于 2026 年选型；
- 评测主要是最终答案准确率，不能证明过程解释完全正确；
- 论文没有报告对儿童教学质量、多轮引导或答案泄露的评测；
- 数据生成和验证都大量依赖 GPT-4 系列，缺少系统的人类步骤级一致性报告；
- 论文宣称做过去重，但没有公开足以复核的 n-gram 阈值、完整来源清单和逐来源重合率。

## 10. 数据质量与可复现性风险

### 10.1 发布物口径不一致

根数据比论文多 7 条；caption、solution 和根数据覆盖范围不同。必须使用 ID 连接并输出数据质量报告，不能按数组索引拼接。

### 10.2 验证集根字段为空

根 `data.json` 中：

- 8,444 条 `val` 记录的 `title_zh`、`title_en`、`solution_zh` 和 `solution_en` 全为空；
- 另有 6 条训练记录也缺少这些字段；
- solution 的验证聊天文件提供 8,443 条记录，仍有 1 个根验证 ID 不在其中。

因此，根文件不是可直接使用的完整训练/验证单一文件。需要分别从 chat 文件恢复对应任务内容。

### 10.3 caption 缺失和视觉幻觉

根数据有 115 条训练记录同时缺少中英文 caption。更重要的是，非空 caption 也不保证正确。

本地抽查样本 `2aab8f1a397e3401ca09846c26e01c3a`：

- 图片中三个物品依次是毛巾 8.60 元、牙膏 3.20 元、香皂 2.20 元；
- `caption_zh` 把中间的牙膏描述成了香皂；
- 解答使用香皂 2.20 元，最终计算恰好仍然正确。

这类错误很危险：只检查最终答案会放过视觉对象识别错误。在另一道题上，同样的对象绑定错误可能直接导致错误提示或错误教学。

### 10.4 解法格式和过程正确性

根数据中有 9,890 条记录的中英文 solution 都没有出现 `\boxed`。其中 8,450 条是解答字段为空，剩余至少 1,440 条属于非空但不符合统一最终答案格式的情况。

此外：

- 多问题可能有多个答案，单个 `boxed` 不足以表达结构；
- “最终答案一致”不代表前面每一步都正确；
- 生成解法可能使用超出六年级课程范围的方法；
- 有些题允许多种方法，而数据通常只给一条路径；
- 解释语言偏书面和模板化，不适合直接语音朗读；
- 完整解法会一次泄露所有步骤，与项目教学原则相冲突。

### 10.5 图片描述不是结构化图形真值

caption 是自然语言段落，不包含：

- OCR 字符框和置信度；
- 图元坐标；
- 点、线、角、边、区域的唯一 ID；
- 平行、垂直、包含、相交等可验证谓词；
- 图片事实与题干推断的来源区分。

它可以作为 DiagramGraph 生成的弱监督输入，但不能作为 DiagramGraph 的最终真值。

### 10.6 训练与评测污染

题目来自教材、练习和考试题库。即使作者使用 n-gram 排除了若干既有公开数据，仍可能与互联网题库、模型预训练语料或我们未来评测集存在近似题、模板题和图片变体。

建立内部评测集时，应至少按以下层级去重：

```text
完全相同 ID/图片哈希
→ 题干规范化后的精确重复
→ n-gram / MinHash 近似重复
→ 数值替换模板重复
→ 图像感知哈希近似重复
→ 数量关系图同构或高相似
```

## 11. 许可证和商用边界

这是当前最需要先解决的非技术问题。

已知事实：

1. GitHub 代码仓库包含 [Apache License 2.0](https://github.com/pengshuai-rin/MultiMath/blob/main/LICENSE)；
2. Hugging Face 数据仓库根目录当前只有数据文件和 `.gitattributes`，没有单独的 README 数据卡或许可证文件；
3. 论文附录说明题目来自学库宝题库，作者购买了使用权，并获得“研究用途”许可；
4. 论文没有明确写出第三方可将题目、图片和派生标注用于商业产品训练、生产知识库或向终端用户再展示。

因此，不能仅因为代码是 Apache-2.0，就推断整个题库及图片也具有相同商用许可。建议：

- 内部研究、技术验证和原型阶段仍保留来源与版本记录；
- 在任何商业训练、生产检索、题目展示或数据再分发之前，联系作者和数据权利方取得书面许可；
- 对进入内部 gold 集的题目记录 `origin`、`source_reference` 和 `copyright_status`；
- 如果不能获得商业授权，只借鉴 schema、训练思想和评测方法，自建或采购权属清晰的数据。

本节是工程风险判断，不构成法律意见。

## 12. 对 voice-tutoring 的实际价值

### 12.1 能力匹配

| 当前项目能力 | MultiMath-300K 价值 | 主要限制 |
| --- | --- | --- |
| 中文题目识别 | 高 | 题干来自题库，但根验证字段不完整 |
| 图片内容描述 | 中高 | 有 29 万级 caption，但存在幻觉和题干条件泄入 |
| 图文联合解题 | 高 | 每题单图且有完整解法，是其主要设计目标 |
| 六年级候选题池 | 高 | 有 41,119 条，但题型分布与 MVP 不完全一致 |
| 教师备课初稿 | 中 | 可提取一条候选解法，需要数学和教学审核 |
| 结构化数量关系 | 低 | 只有自然语言，没有对象与关系图 |
| DiagramGraph | 低 | 无坐标和结构化视觉谓词真值 |
| 学生步骤理解 | 很低 | 没有学生作答、错误步骤或口语表达 |
| 多轮引导教学 | 很低 | 数据是一次性完整回答，不是教学对话 |
| 答案防泄露 | 无直接支持 | solution 天生包含完整步骤和最终答案 |
| 理解验证 | 无直接支持 | 没有复述、纠错或微型变式题标注 |
| 实时语音交互 | 无直接支持 | 没有 ASR、轮次、打断和时延数据 |

### 12.2 最有价值的使用方式

1. **六年级题目发现**：筛出权属允许、图片清晰、题干完整的六年级题目，作为内部审核候选。
2. **视觉回归测试候选**：选择统计图、价格表、路线图、组合图形、圆柱和几何示意图，测试视觉信息抽取。
3. **教师备课预填充**：把 title、caption、solution 和 exam point 转换成教师备课包草稿，再由规则、数学工具和人工审核。
4. **caption 纠错训练**：把发现的错误 caption 转换为“视觉事实核对”负例，训练系统区分看见、读取和推断。
5. **步骤解析研究**：把 `Step X` 解法解析为候选步骤图，研究如何定位依赖关系和首个错误点。
6. **中英一致性检查**：利用双语题干和解法发现翻译造成的数字、对象、条件或答案漂移。

### 12.3 不建议的使用方式

- 不把原始 solution 直接作为实时老师回复；
- 不把 caption 直接当作视觉事实真值；
- 不把整个数据集无清洗放入生产 RAG；
- 不用随机抽取的同源样本评测经过该数据训练的模型；
- 不依据 `exam_point` 单字段直接决定教学策略；
- 不在未确认许可前用于商业微调或向用户展示原题；
- 不用 MultiMath-7B 的旧榜单结果替代当前模型实测。

## 13. 推荐的数据接入方案

### 13.1 分层数据架构

建议保留三层：

```text
Bronze 原始层
  原始 JSON、图片压缩包、来源版本、文件哈希
        ↓
Silver 清洗层
  字段完整、图片存在、题型重标、caption 核对、答案可验证
        ↓
Gold 教学层
  数量关系、多个适龄解法、步骤图、常见错误、提示等级、教学边界、人工审核
```

Bronze 层只做不可变归档。不要直接修改下载的原始文件，否则后续无法复核差异。

### 13.2 标准化记录

建议把 MultiMath 记录转换为当前项目金标准的候选结构：

| MultiMath 字段 | 目标字段 | 转换说明 |
| --- | --- | --- |
| `id` | `source.source_id` | 保留原 ID，不直接作为内部 case ID |
| `grade` | `scope.grade` | 先核对课程内容是否真适龄 |
| `exam_point` | `scope.curriculum_tags` | 作为候选标签，再映射内部 taxonomy |
| `type` | `problem.answer_form` 等 | 不能一对一复制，需要拆分题目结构 |
| `title_zh` | `problem.text` | 去除异常 `<image>`、网页噪声和多余标记 |
| `image` | `source.image_ref` | 只提取被实际引用的图片 |
| `caption_zh` | `perception.caption_candidate` | 标记为未审核弱标注 |
| `solution_zh` | `solution_paths.candidate` | 解析后逐步验证，不直接批准 |

### 13.3 质量门槛

每条进入 Silver 层的数据至少通过：

1. 题干完整且能明确判断要解决的问题；
2. 图片可读，题干引用的视觉信息确实存在；
3. caption 中的数字、物体、标签和几何关系与图片一致；
4. 标准答案可被独立工具或人工复算验证；
5. solution 每一步成立，单位正确，不依赖隐藏条件；
6. 解法符合六年级课程边界；
7. 多问题已经拆成明确子任务；
8. 与训练集和内部评测集完成文本、图片和模板级去重；
9. 来源权利满足预定用途。

进入 Gold 教学层还需要：

- 至少一条适龄解法，必要时补第二种方法；
- 结构化对象和数量关系；
- 步骤依赖图；
- 常见错误和诊断问题；
- L1～L4 提示；
- 答案防泄露规则；
- 理解验证题；
- 数学审核与教学审核双通过。

### 13.4 与实时系统的边界

原始 MultiMath solution 只能在离线教师备课阶段使用：

```text
原始 solution
→ 解析和验证
→ 生成内部教师备课包
→ 标记哪些内容当前允许透露
→ 实时状态机每轮只选择一个教学动作
→ 安全检查后输出语音和黑板更新
```

不要在每轮实时请求里直接检索并注入整篇 solution，否则模型很容易提前泄露最终答案和后续步骤。

## 14. 推荐的验证计划

### 阶段 0：先解决权属

- 联系作者确认数据集许可范围；
- 明确是否允许内部研究、商业模型训练、生产检索和终端展示；
- 在结论明确前不进入商业训练管线。

### 阶段 1：六年级抽样审计

建议按题型和视觉类型分层抽取 300～500 条，而不是简单随机抽样。重点统计：

- 题干完整率；
- 图片可读率；
- caption 事实准确率；
- 最终答案准确率；
- 步骤完全正确率；
- 六年级适龄率；
- 多问拆分成功率；
- 题型标签映射一致率。

视觉类型可先采用人工粗分类：纯公式、几何图、统计图、表格/价目表、路线图、立体图、实物插画、流程图和其他。

### 阶段 2：构建小型 Gold 集

优先选择 100～300 条权属清晰、图片必要、数学关系明确的六年级题，覆盖：

- 百分数应用；
- 行程问题；
- 图文数量关系；
- 统计图读取；
- 组合图形面积；
- 长方体、正方体和圆柱；
- 少量工程和年龄题，并用自建数据补足。

每题使用现有《六年级数学应用题金标准模板》补齐学生步骤、错误类型、提示层级和理解验证。

### 阶段 3：能力拆分评测

不要只评最终答案，应建立：

| 层级 | 指标示例 |
| --- | --- |
| 感知 | OCR 字符准确率、数字/单位准确率、图中对象召回率 |
| 结构 | 对象绑定、数量关系、图形关系准确率 |
| 数学 | 最终答案、首错定位、步骤有效性、单位一致性 |
| 教学 | 下一教学动作、提示最小性、答案泄露率 |
| 交互 | 学生口语步骤对齐、打断恢复、黑板状态一致性 |

### 阶段 4：再决定是否训练

只有在以下条件满足后才考虑用 MultiMath 派生数据训练：

- 许可证明确；
- 抽样质量达到预设门槛；
- 与内部评测集完成严格去重；
- 训练目标是明确的子能力；
- 有独立回归集监控文本数学能力、视觉能力和教学行为退化。

## 15. 综合判断

MultiMath-300K 是目前较少见的、大规模中文 K12 图文数学训练数据。对当前项目而言，它比单纯的最终答案基准更有价值，因为它同时提供题图、题干、图片描述、知识点和逐步解法，而且六年级记录达到 41,119 条。

但它解决的是“模型如何看图并完整解题”，而 `voice-tutoring` 要解决的是“系统如何理解学生当前一步，并在不泄露答案的前提下选择下一教学动作”。两者之间还隔着题目世界模型、步骤图、学生状态、教学策略和安全检查等关键层。

最终建议：

- **作为候选题库和弱标注来源：推荐。**
- **作为视觉数学预训练/微调数据：在许可和质量验证后有条件推荐。**
- **作为六年级教学金标准：不推荐直接使用，必须转换和人工审核。**
- **作为实时语音老师的 RAG 文档：不推荐直接接入。**
- **作为商业产品数据：许可未明确前不推荐。**
- **MultiMath-7B 作为当前基座模型：不能根据 2024 年论文直接决定，需要与现有候选模型重新实测。**
