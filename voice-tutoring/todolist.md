## 1. 文档目的

本文集中记录当前 Demo 已完成、原型完成和尚未实现的能力。状态定义：

- `DONE`：已经接入主业务路径并通过测试。
- `MVP`：完成 Demo 级闭环，仍需要数据评测和生产化。
- `SPIKE`：只有独立技术原型，尚未接入真实业务路径。
- `TODO`：尚未实现。

## 8. 当前实施计划

### 8.1 陌生题动态教师备课包

```text
ConfirmedProblem
→ LLM 提取对象、变量和声明式约束
→ 生成候选解法、核心理解和教学入口
→ SymPy 求解与回代
→ TeacherPreparationPackage
→ 创建辅导会话和 Demo 调试面板
```

MVP 验收：未命中金标准的常规六年级文字应用题能够生成至少一条结构化候选解法；只有通过 SymPy 的答案才能标记为 `ready` 并参与教学。

### 8.2 普通应用题 SymPy 验证

- 使用受限表达式解析器，不直接执行模型生成的 Python。
- 验证方程组可解、目标变量有值、结果满足全部方程。
- 对学生 `normalized_math` 执行可判定的方程一致性或等价性检查。
- 验证失败返回结构化原因，不能把“工具无法验证”判成学生错误。

### 8.3 上传图形题生成并确认 DiagramGraph

- 视觉模型一次返回题目文字和 `DiagramGraphDraft`。
- 每个实体、标注和关系保存稳定 ID、归一化坐标、来源、置信度和状态。
- 确认页展示图形对象、关系与不确定项；有图形时必须确认后才能继续。
- `ConfirmedProblem` 保存已确认图形，供后续教师备课和真实 SVG 黑板使用。

## 9. 状态维护规则

每次实现或调整功能时同步维护本文件：

1. 更新状态，不删除尚未完成的验收标准。
2. `SPIKE` 接入主路径并有测试后才升级为 `MVP`。
3. 只有真实业务闭环和回归测试通过后才标记为 `DONE`。
4. 新增章节时同步维护顶部目录。
